> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans. Track the steps below; preserve all existing frozen artifacts.

**Goal:** Deliver a tested trainable DQN, reproducible checkpoint/evaluation commands and pilot evidence.

**Architecture:** Environment/model, sampling/replay, and training/artifact orchestration are separate modules. Reuse current instance schema, feasibility checks and result conventions.

**Tech Stack:** Existing Python 3.12 venv, NumPy, PyYAML and pinned PyTorch CPU.

**Spec:** `docs/superpowers/specs/2026-10-03-dqn-design.md`.

## Global constraints

- Preserve corpus, `data_manifest.json`, `reference_results.csv`, `baseline_results.csv`.
- Match existing DQN structure and all YAML budgets; use fractional U for selection.
- Use original indices for returned solutions and no test metrics during training.
- Run in the user's existing checkout/venv; do not create a second data/environment copy.

## Review focus

- Padding and terminal states must not contaminate pooling or bootstrapping.
- Replay and episode sampling must both retain source balance.
- Cached inference must equal the ordinary network policy.
- A stale corpus/reference/config must not silently produce comparable-looking results.
- Existing output directories and CSVs must survive accidental repeated commands.
